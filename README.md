# 有點濕濕的 · Misty Water Lab Interactive

原生 HTML / CSS / JavaScript，Three.js **0.170.0** 透過固定版本 CDN import map 載入。不需要 Node.js、npm 或建置步驟。Shader 位於 `main.js` 的 `vertexShader` 與 `fragmentShader`。

## 開啟

1. 用 VS Code 開啟本資料夾。
2. 安裝擴充套件 **Live Server**（Ritwick Dey）。
3. 在 `index.html` 按右鍵，選 **Open with Live Server**。
4. 瀏覽器通常開啟 `http://127.0.0.1:5500/`。第一次載入需要網路下載 Three.js。

請用 HTTP 伺服器開啟，勿直接雙擊使用 `file://`。遇到啟動失敗時，頁面會顯示訊息；可在開發者工具 Console 查看原因。

## 操作與設計

- 右下角實驗室：水滴密度、大小、折射程度、霧氣濃度、滑落速度。
- 手機預設收起面板，點「玻璃實驗室」展開。
- 「重新凝結」產生新的隨機分布；「暫停」停止滑落；輕觸玻璃產生短暫柔光。
- 大量靜止凝結水珠保留在玻璃上，另有少量較大水滴獨立滑落。
- 新增「滑落比例」（以較大凝結水珠數量為基準，上限 14 顆）、「拖尾長度」、「水痕強度」，並保留「滑落速度」。
- 各顆水滴有不同的速度、延遲、停頓與滑落距離；下方圓潤主體與向上延伸的細尾共同形成厚度圖，Shader 依厚度梯度計算折射與高光。水痕沿已滑過的路徑留在主體上方。
- 滑過處留下細窄、透明的水痕，約數十秒內淡去；遇到的小水珠會消失，大水滴按吸收體積平滑增大。原位置之後逐漸重新凝結。
- 「暫停」會同時停止滑落與水痕消退。「滑落速度」為 0 時也會凍結時間。
- 開啟系統「減少動態效果」時預設暫停，可手動繼續。
- 背景由 Canvas 生成模糊霧藍影像，沒有額外圖片依賴。
- DPR 上限 1.5，繪製像素約上限 180 萬；手機 30 fps、桌面 45 fps，隱藏分頁停止繪製。
- 靜止水滴由 fragment shader 計算；`water.js` 負責滑落、接觸吸收，以及有尺寸上限的 Canvas 厚度／水痕貼圖。這是視覺與體積近似，並非完整流體物理。
- 攝影機僅於按下「啟動攝影機」後請求權限，用於本機手勢辨識；不錄影、不儲存、不上傳影像，沒有 Firebase。

## 局部密集凝結區

`condensation.js` 以多個隨機旋轉的橢圓場疊加，搭配不同尺度的雜訊扭曲、柔和邊緣與內部密度變化，產生低解析度濕氣貼圖。只有種子、螢幕比例或區域參數改變時才重建。Shader 在濕氣區內疊加淡霧膜、兩層微水珠與少量中型水珠，維持霧藍底色與水滴折射，不使用白色雲朵圖片。

本互動版把凝結區依序分散到上、右、下、左四邊，每區尺寸、角度與扭曲各異。中央約 58% 寬、55% 高的小水滴密度平均降低約 60–70%，以柔和扭曲場過渡；大型靜止水滴減少幅度較小。密度場儲存在濕氣貼圖 B 通道，CPU 吸收候選也使用相同分布函式。當滑落水滴數量至少兩顆時，其中一顆由中央上方生成，緩慢穿越繪畫區並留下長水痕；手機僅有一顆滑落水滴時，交替生成中央穿越水滴及原有水滴。滑落比例、速度、暫停及拖尾控制仍有效。背景縮小亮區、降低中央亮度，右側改為較深灰藍，擦拭會露出背景形成較深的透明筆觸。

- **凝結區數量**：0–8，設為 0 可關閉區域及後續區域水滴的生成。
- **凝結區濃度**：控制局部霧膜與聚集水珠的濃淡。
- **凝結區大小**：控制擴散範圍，邊緣持續柔和、不規則。
- **微水珠密度**：控制兩層細小水珠，不影響原有大水滴。
- **凝結區模糊程度**：控制區域內背景擴散與對比降低。

區域大水滴從霧團內的濕潤位置生成，先固定位置逐漸長大（10–22 個模擬秒），等待短暫時間後才向下滑落，拖尾留在上方。預設速度下約需 20–45 秒長成；暫停或速度為 0 時不成長。滑落比例為 0 時不生成滑落水滴。既有水滴不會因關閉凝結區突然消失。

測試時先點「重新凝結」，觀察約一分鐘；可暫時將滑落速度調成 1–2 加快檢查。依序把區域數量設成 0 / 4 / 8、濃度和模糊調成 0 / 1，再比較微水珠密度 0 / 1。區域中心應較濃，邊緣漸淡；拉高拖尾長度仍應向主體上方延伸。右側面板可捲動，標題及原有版面不變。

## 玻璃擦拭互動

用滑鼠左鍵拖曳或單指滑動擦開霧膜。擦拭使用 Pointer Events 與 pointer capture；只在玻璃畫布禁止原生觸控捲動，面板仍可捲動及調整滑桿。快速滑動的寬度與力度略大，柔軟的不對稱筆刷會沿整段路徑插值，避免快速移動斷線。小水珠依方向輕微位移，不因擦拭被直接隱藏。原有折射、高光、拖尾、滑落水痕及凝結區參數均保留。

- **擦拭強度**：0.2–1.5，控制每次經過的清除力度。
- **擦拭範圍**：0.5–2，以螢幕高度為基準，手機直橫向維持比例。
- **重新起霧速度**：0.5–2。最後一筆後所有筆觸至少保留 20 秒，再用約 10 秒淡去；2 加倍淡去速度，0.5 減半。此滑桿不縮短 20 秒保留時間。

`wiping.js` 保留一張低解析度離屏 Canvas，RG 記錄方向、alpha 記錄霧膜清除量。筆畫只在輸入時追加，回霧以最多 20 Hz 更新現有遮罩，完全回霧後停止上傳。遮罩高度上限 384、寬度上限約 512，不建立逐幀 DOM 元素。旋轉螢幕保留歸一化軌跡；「重新凝結」清除軌跡。擦拭及回霧不受水滴暫停或滑落速度影響；隱藏分頁時停止更新。

透過 Live Server 開啟 `tests/wiping.html` 可驗證連續筆畫、範圍外不變、20 秒保留、之後部分回霧及清空、旋轉保留、重設、實際 WebGL 編譯及三個滑桿。另執行 `tests/water.html` 檢查既有水滴效果。若有 Node，也可以執行 `node tests/serve.cjs`，開啟 `http://127.0.0.1:5501/tests/wiping.html`。

手動驗收：比較快慢拖曳與重複擦同一區；停止後等待 20 秒確認仍保留，再等約 10 秒觀察回霧；拖曳離開畫布後放開；手機滑動玻璃應不捲頁，右側面板仍能捲動及調參。手機實際效能與觸控手感需在實機確認。

## 攝影機食指繪畫

使用 [MediaPipe Hand Landmarker 官方 Web API](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)，固定 `@mediapipe/tasks-vision` 0.10.21 與 float16 Hand Landmarker 模型 v1。`vendor/mediapipe-0.10.21.js` 是官方 CJS bundle 的原樣副本，由本機用 JavaScript MIME 提供給 classic worker，旁附 Apache 2.0 授權。WASM 執行檔由 jsDelivr、模型由 Google Storage 下載，故首次啟動需要網路；影像只透過 ImageBitmap 傳到同一瀏覽器的 Worker。

`hand-worker.js` 在 Worker 偵測單手 21 個關鍵點，優先 GPU、失敗時改 CPU。最多約 15 次／秒推論、輸入寬度 480 像素、同時最多一張待處理影格，避免排隊或阻塞 Three.js 主畫面。`hand-camera.js` 管理權限、模型載入、視訊來源、錯誤、關閉與過期影格；離開頁面會關閉串流。載入失敗、權限拒絕或無相機時仍可用滑鼠／觸控。

`gestures.js` 用世界座標的指節角度與伸展程度判斷食指伸直、其餘三指彎曲，拇指不限；沒有以單純的上下座標判定，因此容許手部旋轉。連續兩個有效影格才啟筆；手勢不符、手部消失、追蹤跳躍或影格間隔過長即斷筆。筆尖使用 landmark 8，水平鏡像一次，以時間感知的平滑與小幅防抖降低亂跳。跨越參數面板或手勢按鈕區的線段不繪製，離開後重新起筆；滑鼠拖曳時優先使用滑鼠輸入。

1. 用 Live Server 開啟 `index.html`，確認網址為 `http://localhost:5500/` 或 `http://127.0.0.1:5500/`（連接埠依設定）。
2. 點「啟動攝影機」，允許權限，等待模型載入。依序檢查「未偵測 → 已偵測 → 正在繪畫」。
3. 食指伸直，其餘三指收起，左右移動應符合鏡子方向；連畫圓圈或文字，觀察連續性。握拳、伸兩指、張掌或移出鏡頭應停止；重新比 1 不可連回上一筆。
4. 點「清除筆觸」只清除擦霧，不重設水滴；「重新凝結」則重設水滴及筆觸。關閉攝影機後確認瀏覽器攝影機指示消失，滑鼠仍能繪畫。
5. 點選／捲動右側面板，手勢或滑鼠不得在其後畫線。檢查原有各個參數及暫停仍有效。

`tests/gestures.html` 預設使用合成關鍵點測試姿勢分類、旋轉、鏡像、斷筆、跳點、面板阻擋及密度分布，**不會自動開攝影機**。加上 `?camera=1` 會額外啟動攝影機，測試模型實際推論、狀態及啟停。`tests/browser-check.cjs` 是本機 Windows Chrome 的可選測試工具；`--camera` 使用 Chrome 模擬攝影機，適合驗證模型與權限流程，不能取代真實手部辨識測試。使用者的真實權限提示、左右手、遮擋、現場光線／距離與手機 FPS 仍需實機驗收。

## 手機連線

電腦與手機連接相同 Wi-Fi，可用 `http://電腦的區域網路IP:5500/` 測試滑鼠／觸控畫面（需讓 Live Server 監聽區域網路並允許防火牆）。**手機要使用攝影機必須以有效 HTTPS 開啟**；電腦的區網 HTTP 位址不屬於安全的 localhost。請使用信任的 HTTPS 開發設定或手機本機伺服器。

## 滑落效果驗收

1. 維持預設值觀察 30–60 秒：大多數水珠應靜止，少量較大水滴慢慢滑落，偶爾停頓。
2. 把「拖尾長度」從 0 調至 2，應看到細尾從下方圓潤主體向上延伸；主體繼續向下滑，折射與邊緣高光仍應存在。
3. 暫將「水痕強度」調至 1，比較滑過處的淡水痕，再調回約 0.35。
4. 把「滑落比例」調至 0，滑動水滴應逐漸隱去，保留靜止水珠；重新提高比例後應再次出現。
5. 觀察大水滴接近小水珠時，小水珠消失、大水滴緩緩增厚。可暫提高速度與比例，加快檢查。
6. 暫停後等待：水滴位置與水痕應凍結；「重新凝結」應清除舊水痕並換成新分布。

也可以透過 Live Server 開啟 `tests/water.html`，執行滑落、接觸吸收、記憶體上限、暫停、比例歸零、重新凝結與實際 WebGL Shader 的回歸檢查。完成後應顯示 `ALL CHECKS PASSED`。本機已使用 Chrome 無視窗模式與軟體 WebGL 通過檢查；手機實機的流暢度仍需個別測試。
